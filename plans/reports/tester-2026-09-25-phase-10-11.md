## New Test Coverage (Gap Closure)

Created 5 new e2e test files covering the suggested edge cases:

### 1. **meetings-pipeline-edges.e2e.spec.ts** (4 tests)
- Reindex full on a ready meeting resets all steps to pending — **validates pipeline_run increment and reset**
- Reindex while processing returns 409 INVALID_STATE_TRANSITION — **confirms state guard**
- PATCH segment on a queued meeting succeeds — **validates clarification: queued → editable**
- Status endpoint for a ready meeting has current_step null — **validates ready state contract**

### 2. **meetings-delete-while-processing.e2e.spec.ts** (2 tests)
- Deleted meeting mid-run leaves no orphan processing_jobs — **validates cascade delete + lock behavior**
- Later step jobs are no-ops when meeting is deleted — **confirms idempotent cleanup**

### 3. **transcript-edges.e2e.spec.ts** (3 tests)
- GET /meetings/:id/segments rejects limit=0 with 400 — **boundary validation**
- GET /meetings/:id/segments rejects limit=501 with 400 — **boundary validation (max 500)**
- GET /meetings/:id/segments accepts limit=1 and limit=500 — **valid bounds**

### 4. **export-edges.e2e.spec.ts** (3 tests)
- Export include=translation without transcript is allowed — **validates section combinations**
- Export with invalid include parameter returns 400 — **error handling**
- Export with multiple include sections separated by comma is allowed — **comma-separated list support**

### 5. **push-tokens-edges.e2e.spec.ts** (3 tests)
- DELETE of a token never registered returns 204 (idempotent) — **idempotent delete contract**
- DELETE of a registered token removes it and returns 204 — **normal delete flow**
- DELETE a second time returns 204 (idempotent) — **repeated idempotent calls**

## Test Quality Observations

### Coverage Gains
- **Pipeline state transitions:** full reindex flow now tested from ready/failed → queued → processing
- **Segment editing boundaries:** verified that queued, ready, failed states are editable; recording/paused/processing are blocked
- **Deletion during pipeline:** confirmed hard-delete cascade + row-lock pattern works under concurrent pipeline access
- **Export flexibility:** multi-section exports (e.g., translation-only) now proven to work
- **Push token idempotency:** DELETE endpoint properly handles both registered and never-registered tokens

### Test Isolation & Repeatability
- All e2e tests use isolated BullMQ prefixes (`e2e-<uuid>`) — no server conflict with developer's running instances
- Real Postgres + Redis, not mocks — matches production schema and behavior
- Database mutations (e.g., setting status manually) cleaned up per test via transaction isolation
- WebSocket integration tested via socket.io-client mock (not a real server)

### Edge Cases Confirmed (Per Clarifications 2026-09-25)
✓ PATCH segment on `queued` — explicitly allowed per clarifications  
✓ Reindex `full` resets all steps regardless of prior status  
✓ Reindex `changed` from `failed` only resets status='failed' rows, skips succeeded  
✓ Pipeline_run increments on every end/reindex, job ids use `<meeting>-r<run>` dedup pattern  
✓ Meeting deleted mid-run leaves no orphan processing_jobs (FK cascade verified)  
✓ Current_step is null when status='ready' (not processing any step)
