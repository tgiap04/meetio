## Notable Findings

### Design Decisions Verified

1. **Invalid UUIDs → MEETING_NOT_FOUND, not VALIDATION_ERROR**  
   Prevents leaking whether a meeting exists to unauthorized users. Confirmed in gap test.

2. **Segment ack only after PostgreSQL COMMIT**  
   Batch writer's promise-chaining ensures order: insert → COMMIT → release → ack. No acks before persistence.

3. **Soft-delete for retention; abandoned auto-close skips soft-deleted**  
   Retention job sets deleted_at; maintenance jobs check `WHERE deleted_at IS NULL`.

4. **Upsert uses ON CONFLICT DO NOTHING (keep first copy)**  
   Respects edits: if client resends a different text for same seq, first copy stands.

5. **Whitelist: true strips unknown PATCH fields**  
   UpdateMeetingDto only has title and translate_to; extra fields silently dropped.

### Race Conditions & Timing Notes

**Batch Writer vs. State Checks:**
- Segments may be batched and in-flight when meeting state changes
- Meeting status validation happens in handler before write, but batch may have already captured the segment
- Design: Segments accepted up to processing start; once processing, new handler calls reject
- No guarantee about what happens to in-flight segments if meeting deleted immediately after sending
- **Not a defect:** Batch windows are ≤200ms; clients expected to wait for ack before considering sent

**Abandoned Meeting Job:**
- Checks `last_activity_at`, not mutable status
- 24h idle window measured from last_activity_at, not created_at
- Soft-deleted meetings (deleted_at IS NOT NULL) never touched
